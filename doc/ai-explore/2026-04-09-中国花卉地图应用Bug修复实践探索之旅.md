## 八、AI 辅助调试经验（面向 AI 学习者）

```mermaid
mindmap
  root((Claude Code\n辅助调试))
    源码阅读策略
      直接 grep node_modules
      找默认配置值
      理解内部状态机 kapsule
    HTTP 诊断技巧
      curl 批量验证
      404 vs 429 精确区分
      CDN 缩略图生成规则
    React 常见陷阱
      async 回调闭包陷阱
      useRef 保持最新 props
      useCallback 引用稳定性
      kapsule 引用相等性检测
    测试分层原则
      单元测试覆盖纯逻辑
      E2E 覆盖视觉交互
      WebGL headless 局限性
    稳健性设计
      fallback 零外部依赖
      data URI 本地生成
      降级方案不引入新依赖
    提示词工程
      精确描述胜过模糊描述
      截图 + 文字双重佐证
      迭代优化直到命中根因
```

| 经验 | 核心教训 |
|------|---------|
| 读三方库源码 | 很多"玄学 Bug"根因就在 `node_modules` 的默认配置值 |
| HTTP 状态码精确含义 | 404 ≠ 429；混淆会导致错误结论和无效修复 |
| fallback 不依赖外网 | fallback 引入新外部依赖反而更脆，data URI 才是真正的保底 |
| Agent 也有速率限制 | 后台 Agent 可能因 token 配额失败，核心工作不依赖 Agent 结果 |
| 提示词需要迭代 | 用户用 3 条提示词才准确描述出 Bug 2，精确描述是高效协作的基础 |
